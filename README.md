# Swupでページをまたいで音声再生を維持するサンプル

複数のHTMLページを持つウェブサイトで、ページを移動してもBGMの再生位置と再生／停止の状態を維持するサンプルです。

ページ遷移ライブラリの[Swup](https://swup.js.org/)を使い、ページ全体を再読み込みせずにメインコンテンツだけを差し替えています。フレームワークやビルドツールを使わないため、HTML・CSS・JavaScriptの役割を小さな構成で確認できます。

## このサンプルで確認できること

- Swupによるページ遷移とフェードアニメーション
- Swupの差し替え範囲の内側／外側で、DOM要素の扱いがどう変わるか
- ページを移動しても音声の再生位置と再生／停止状態を維持する方法
- Swupによる遷移後に、ページ固有のJavaScript処理を実行する方法
- ブラウザの自動再生制限を考慮して背景動画を再生する方法

## Swupとは

Swupは、サーバーから配信される通常の複数ページ構成のウェブサイトに、滑らかなページ遷移を加えるJavaScriptライブラリです。

通常、別のHTMLページへのリンクをクリックすると、ブラウザは現在のページを破棄して次のページ全体を読み込みます。Swupは代わりにリンクのクリックを検知し、リンク先のHTMLをバックグラウンドで取得して、指定されたコンテンツ部分だけを差し替えます。URLとブラウザ履歴も更新されるため、戻る／進む操作も利用できます。

このプロジェクトでは特別な設定を渡さず、次のコードでSwupを初期化しています。

```js
const swup = new Swup();
```

Swupの初期設定では、各ページの`id="swup"`を持つ要素が差し替え対象になります。

```html
<main id="swup" class="transition-fade">
  <!-- ページごとに変わる内容 -->
</main>
```

`#swup`の外側にある要素は差し替えられず、現在のページに残り続けます。この境界が、本サンプルで音声状態を維持するための要点です。

## 本プロジェクトでのSwupの用途

各HTMLファイルの構造は、概ね次のようになっています。

```text
body
├── audio              ← 差し替え範囲の外：同じ要素が残る
├── header             ← 差し替え範囲の外：同じ要素が残る
│   └── 音声再生ボタン
├── main#swup          ← ページ移動時に中身が差し替わる
│   └── ページ固有の内容
└── footer             ← 差し替え範囲の外：同じ要素が残る
```

Swupが担当するのは、主に次の3点です。

1. サイト内リンクのクリックを受け取り、リンク先のHTMLを取得する
2. 現在の`main#swup`を、リンク先ページの`main#swup`に差し替える
3. CSSの状態クラスとライフサイクルフックを提供する

`css/style.css`では、Swupが`html`要素に付ける`is-changing`と`is-animating`を利用して、`main`の透明度を変化させています。

## 音声の再生状態が維持される仕組み

音声要素は、すべてのHTMLファイルで`#swup`の外側に置いてあります。

```html
<audio id="audio" hidden loop preload="auto">
  <source src="./audio/aviansho9-mood-1-188071.mp3" type="audio/mpeg">
</audio>
```

Swupによるページ移動では`#swup`の中だけが差し替えられるため、この`audio`要素は破棄も再作成もされません。同じ要素が再生を続けるので、次の状態がそのまま維持されます。

- 再生中か停止中か
- 現在の再生位置
- ループ再生の進行

音声ボタンも`#swup`の外側にあり、`js/app.js`がクリックイベントを一度だけ登録します。音声の`play`／`pause`イベントが発生すると、ボタンのアイコンを現在の状態に合わせて更新します。

なお、ブラウザでページを再読み込みした場合や、Swupが処理しない方法で別ページを開いた場合は、通常どおり新しいHTML文書になります。その場合、音声の状態は維持されません。このサンプルが状態を維持できるのは、Swupが同じ文書内で`#swup`だけを差し替えているためです。

## トップページの動画とSwupでの考慮事項

トップページの背景動画は`main#swup`の内側にあります。

```html
<video
  class="hero-video"
  poster="images/39220-421020366.webp"
  muted
  loop
  playsinline
  preload="auto"
>
  <source src="./video/39220-421020366.mp4" type="video/mp4">
</video>
```

音声とは異なり、トップページを離れると動画要素は`#swup`とともに削除されます。別ページからトップページへ戻ると、新しい動画要素が挿入されます。

ここで注意したいのは、Swupによるページ遷移では`app.js`そのものが再実行されず、`DOMContentLoaded`も再度発生しないことです。最初のページ読み込み時にだけ動画を再生するコードでは、Swupでトップページへ戻った際の新しい動画を扱えません。

そのため、このサンプルでは動画再生関数を次の2つのタイミングで呼び出します。

```js
// 最初のHTML読み込み時
startVideo();

// Swupによるページ表示後
swup.hooks.on("page:view", startVideo);
```

`page:view`は、Swupが新しいページを表示した後に実行されるライフサイクルフックです。毎回その時点のDOMから`.hero-video`を探し、存在する場合だけ`play()`を呼び出します。

### 自動再生への配慮

多くのブラウザは、音の出るメディアの自動再生を制限しています。背景動画には次の指定を行っています。

- `muted`: 動画を消音し、自動再生が許可されやすい状態にする
- `playsinline`: 対応するモバイルブラウザで全画面に切り替えず、ページ内で再生する
- `loop`: 動画を繰り返し再生する
- `poster`: 動画の読み込み前や再生できない場合に静止画を表示する

HTMLの`autoplay`属性だけに任せず、初回表示とSwup遷移後の両方で`play()`を呼びます。`play()`はPromiseを返し、自動再生が拒否されると失敗するため、`.catch()`でエラーを捕捉しています。

```js
video.play().catch((error) => {
  console.error("動画を再生できませんでした。", error);
});
```

`muted`を指定していても、端末・ブラウザ・省電力設定などによって必ず再生できるとは限りません。再生できない場合でも`poster`画像が背景として残ります。

## 処理の流れ

### 最初にページを開いたとき

1. ブラウザがHTML、CSS、Swup本体、`app.js`を読み込む
2. `new Swup()`でSwupを初期化する
3. 音声要素と再生ボタンを取得し、イベントを登録する
4. トップページに動画があれば`startVideo()`で再生を試みる

### Swupでページを移動したとき

1. Swupがサイト内リンクのクリックを受け取る
2. 現在の`main#swup`をフェードアウトする
3. リンク先HTMLの`main#swup`と差し替える
4. 新しい`main#swup`をフェードインする
5. `page:view`フックから`startVideo()`を呼ぶ
6. `#swup`の外側にある音声は、同じ位置から再生または停止状態を継続する

## 動かし方

### メディアファイルを用意する

音声・動画・ポスター画像は、このリポジトリには含まれていません。動作確認の前に、以下の手順で各自用意してください。

1. [音声「Mood 1」の素材ページ](https://pixabay.com/music/beats-mood-1-188071/)から音声をダウンロードする
2. プロジェクト直下に`audio`ディレクトリを作り、音声を`audio/aviansho9-mood-1-188071.mp3`として配置する
3. [動画「Clouds, Light, Sea」の素材ページ](https://pixabay.com/videos/clouds-light-sea-sunrise-sun-rays-39220/)から動画をダウンロードする
4. プロジェクト直下に`video`ディレクトリを作り、動画を`video/39220-421020366.mp4`として配置する
5. 動画の任意のフレームをキャプチャしてWebP形式に変換するか、権利上利用可能な別の画像を用意する
6. プロジェクト直下に`images`ディレクトリを作り、ポスター画像を`images/39220-421020366.webp`として配置する

ポスター画像は、動画を読み込む前や動画を再生できない場合に`<video>`要素の`poster`属性で表示されます。動画からのキャプチャには、動画編集ソフト、メディアプレーヤーのスクリーンショット機能、FFmpegなど、任意の方法を利用できます。別の画像を使う場合は、必要に応じて`index.html`の`poster`属性のパスを変更してください。

ダウンロードおよび利用にあたっては、各素材ページと最新のPixabay Content Licenseを確認してください。これらのディレクトリは`.gitignore`の対象であり、用意したメディアファイルはGitに追加されません。

### ローカルWebサーバーで表示する

Swupはリンク先のHTMLを`fetch`で取得します。`index.html`をファイルとして直接開くのではなく、VS CodeのLive PreviewなどのローカルWebサーバーから表示してください。

確認手順:

1. 右下の音声ボタンを押してBGMを再生する
2. About、Works、Contactへ移動する
3. BGMが途切れず、再生位置も戻らないことを確認する
4. 音声を停止してから別ページへ移動し、停止状態が続くことを確認する
5. Homeへ戻り、背景動画が自動で再生されることを確認する
6. ブラウザの再読み込みでは音声状態がリセットされることを確認する

## 初学者向けの学習ポイント

- DOM要素を「同じ見た目」ではなく「同じ実体かどうか」で考える
- Swupが差し替える範囲と、残し続ける範囲を意識する
- 初回読み込みとSwupによるページ表示は、異なるライフサイクルである
- `play()`のような非同期処理は、失敗する場合も扱う
- ブラウザの自動再生ポリシーを前提にメディアを設計する
